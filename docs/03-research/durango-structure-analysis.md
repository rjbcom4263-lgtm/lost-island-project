# 듀랑고 구조 해부 — 사라진섬 설계를 위한 연구 문서

> 목적: 기존 작품을 복제하기 위한 문서가 아니라, **왜 듀랑고의 세계와 시스템이 서로 잘 맞물렸는지**를 구조적으로 분석하고 사라진섬 프로젝트에 적용할 일반 원리를 추출한다.

## 0. 한 줄 요약

듀랑고의 핵심은 `공룡 생존 게임`보다 **정착 → 탐험 → 자원 확보 → 가공/제작 → 건축/사회 → 더 위험한 탐험**이 반복되는 개척 순환 구조에 있다.

---

## 1. 세계관 구조

### 1.1 진입 장치

- 현대인이 알 수 없는 현상으로 낯선 세계에 떨어진다.
- 처음부터 세계의 정답을 설명하지 않고, 플레이어가 생활과 탐험을 하며 세계를 이해하게 한다.
- 현실의 지식과 원시 생태계가 충돌하기 때문에 튜토리얼과 생존 학습이 세계관 자체가 된다.

### 1.2 섬이 세계의 기본 단위

듀랑고 세계는 하나의 고정된 대륙보다 여러 섬/군도 단위로 구성됐다.

- **정착용 공간**: 오래 머물고 건축과 공동체를 만들기 좋다.
- **위험/탐험 공간**: 더 좋은 자원과 생태계를 제공하지만 불안정하고 사라질 수 있다.
- 플레이어 수와 플레이 상황에 따라 새로운 섬을 공급할 수 있는 구조였다.

이 설계가 중요한 이유는 `집을 꾸미는 게임`과 `계속 여행하는 게임`을 동시에 성립시키기 때문이다.

### 1.3 미스터리의 역할

세계의 미스터리는 스토리 전용 장치가 아니라 시스템을 설명한다.

- 왜 서로 다른 시대의 생물이 함께 존재하는가?
- 왜 섬이 나타나고 사라지는가?
- 왜 특정 장소에 특이 자원과 강한 생물이 존재하는가?
- 왜 이동 장치가 필요한가?

좋은 세계관 장치는 **게임 규칙을 자연스럽게 설명하는 장치**이기도 하다.

## 2. 핵심 게임 루프

```text
정착지
  ↓ 준비
탐험 섬 진입
  ↓
발견 / 채집 / 사냥
  ↓
위험 관리
  ↓
귀환
  ↓
가공 / 제작
  ↓
건축 / 연구 / 성장
  ↓
더 먼 탐험
```

이 루프는 네 개의 작은 루프가 서로 연결된다.

### 2.1 탐험 루프

`새 섬 → 미지의 지형 → 생물/자원 발견 → 위험 → 보상`

섬이 변하거나 사라지기 때문에 탐험이 한 번 끝나도 세계 전체가 완전히 소모되지 않는다.

### 2.2 생산 루프

`원재료 → 가공 → 부품/재료 → 도구/장비/음식 → 고급 제작`

단순한 레시피 해금보다 재료의 속성과 가공 단계가 중요해서 경제와 전문화가 생긴다.

### 2.3 정착 루프

`임시 캠프 → 작업대 → 저장 → 집 → 농장 → 마을/거점`

플레이어가 세계를 소비하는 데서 끝나지 않고 **세계에 흔적을 남긴다.**

### 2.4 사회 루프

`개인 전문화 → 부족/클랜 → 역할 분담 → 공동 시설 → 거래/경쟁`

한 캐릭터가 모든 생산 체계를 동시에 최고 수준으로 수행하기 어렵게 만들면 자연스럽게 협력과 거래가 발생한다.

## 3. 시스템 간 연결 구조

### 자원

자원은 단순한 아이템 드롭이 아니라 거의 모든 시스템의 출발점이다.

```text
생태계
 ├ 식물
 ├ 광물
 └ 동물
     ↓
   채집
     ↓
   가공
     ↓
 ┌───┼────┐
도구 장비 음식 건축재
 └───┼────┘
     ↓
 더 위험한 지역
```

### 스킬

스킬 카테고리는 전투뿐 아니라 채집·가공·건축·요리·농사 같은 생활 행동과 연결된다.

핵심 원리:

1. 행동이 성장과 연결된다.
2. 성장하면 더 좋은 생산 수단을 얻는다.
3. 더 좋은 생산 수단은 더 위험한 탐험을 가능하게 한다.
4. 탐험 결과가 다시 제작과 건축으로 돌아온다.

### 동물

동물은 몬스터 하나의 역할만 하지 않는다.

- 위협
- 사냥감
- 생태계 요소
- 자원 공급원
- 발견 대상
- 이동/운송 수단
- 길들이기 대상

따라서 동물 시스템이 탐험, 전투, 제작, 운송, 수집을 한 번에 연결한다.

## 4. 월드 구조

### 4.1 공간 계층

NDC 서버 아키텍처 자료를 단순화하면 다음과 같다.

```text
세계
 └ 군도
    └ 섬
       └ 타일맵
          └ Chunk (16×16 타일)
             ├ 자연물
             ├ 시설물
             ├ 동물
             └ 플레이어
```

청크는 공간 스트리밍, 데이터 인덱싱, 영속 저장의 좋은 경계가 된다.

### 4.2 영속 세계

핵심 철학은 플레이어가 나가도 세계가 기억되어야 한다는 것이다.

- 건축물
- 자연물 변화
- 농장/시설
- 위치 기반 객체

등을 월드 상태로 저장한다.

### 4.3 신기루 방식 — 필요할 때만 활성화

듀랑고 서버는 모든 나무와 동물을 항상 고비용 객체로 시뮬레이션하지 않았다.

정적 객체는 평소 최소 정보만 유지하고, 플레이어가 상호작용할 때 활성 객체가 된다. 동물도 플레이어가 가까이 있을 때 고수준 AI를 돌리고 관찰자가 사라지면 상태를 저장한 뒤 비활성화한다.

사라진섬에 적용할 일반 원리:

```text
멀리 있음
 = 데이터만 존재

플레이어 접근
 = 시뮬레이션 활성화

플레이어 이탈
 = 상태 저장 + Sleep
```

소규모 멀티에서도 매우 유용한 최적화다.

## 5. 서버 구조에서 배울 점

원작 MMO 규모를 그대로 따라갈 필요는 없지만 역할 분리 개념은 유용하다.

| 원작 개념 | 역할 | 사라진섬 축소판 |
|---|---|---|
| Frontend | 플레이어 접속/주변 상태 전송 | Game Session / Player Replication |
| Gateway | 로그인/접속 라우팅 | 간단한 Lobby/Auth |
| Zoo | 동물 시뮬레이션 | AnimalSystem |
| Garden | 식물·광물·시설물 | WorldObjectSystem |
| Colosseum | 전투 판정 통합 | CombatSystem |
| Land Document | 위치 기반 영속 객체 색인 | ChunkSave |

우리 목표가 2~8인이라면 서비스 프로세스를 다섯 개로 나눌 필요는 없다. **코드 모듈만 분리하고 하나의 서버 프로세스에서 시작**한다.

## 6. 사라진섬에 가져올 설계 원리

### 가져온다

- 안전한 정착과 위험한 탐험의 대비
- 영구적으로 기억되는 플레이어 흔적
- 섬 단위 콘텐츠 공급
- 청크 기반 월드 저장/스트리밍
- 채집→가공→제작→건축의 긴 생산 사슬
- 동물을 다목적 시스템으로 활용
- 서버 권위형 월드 상태
- 필요할 때만 생태계를 활성화하는 Sleep/Wake 구조

### 새로 만든다

- 세계가 갈라진 원인
- 이동/귀환 원리
- 섬의 분류와 명칭
- 자원과 에너지 체계
- 세력/조직
- 생물 종과 생태
- 모든 아이템/스킬/레시피/건물 이름 및 수치
- UI, 아트, 음악, 캐릭터, 스토리

### 복제하지 않는다

- 원작 상표/로고
- 원작 고유 명칭을 제품 설정으로 재사용
- 원작 코드/에셋/데이터 테이블의 직접 복사
- 원작 맵/퀘스트/문장/아이콘의 재사용
