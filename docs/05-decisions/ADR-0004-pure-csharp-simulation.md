# ADR-0004: 게임 규칙은 순수 C# 공용 코드로 분리한다

- 상태: 승인
- 날짜: 2026-11-10
- 관련: [ADR-0002](ADR-0002-single-multiplayer.md)를 구체화한다

## 결정

채집·제작·건축·전투·생물 판단·저장 같은 게임 규칙(**Simulation**)은 `UnityEngine`을 참조하지 않는 **순수 C# 코드**로 작성한다.

- Unity 클라이언트는 Simulation의 결과를 화면에 그리고, 입력을 요청(`GatherRequest`, `AttackRequest` 등)으로 바꿔 전달한다.
- Simulation 코드는 Unity 에디터 없이 `dotnet test`로 테스트할 수 있어야 한다.
- 싱글에서는 Simulation을 클라이언트 프로세스 안에서 실행하고, 멀티(Phase 3)에서는 같은 코드를 전용 서버에서 실행한다.

## 이유

- 온라인 게임 회사가 흔히 쓰는 "서버가 규칙의 주인, 클라이언트는 표현" 구조를, 2인 팀에 맞게 공용 C# 코드 하나로 줄인 방식이다.
- 에이전트가 Unity 에디터 없이 테스트를 돌리고, 실패를 보고, 고칠 수 있다. 에이전트 중심으로 개발하는 팀에 가장 잘 맞는다.
- 프로그래머(CS 전공, Unity는 처음)에게 익숙한 일반 C# 코드다.
- 싱글로 먼저 만든 뒤 멀티를 붙일 때 다시 짜는 비용이 없다.

## 결과

- 처음 뼈대를 잡는 데 일반 Unity 방식보다 며칠이 더 든다.
- 위치·벡터 같은 기본 타입을 Unity 타입 대신 Simulation 쪽 타입으로 두고, 클라이언트에서 변환해야 한다.
- 물리 충돌처럼 Unity에 의존하는 판정은 어디서 결정할지 기능마다 정해야 한다. 판정 결과가 게임 상태를 바꾸면 Simulation이 최종 결정한다.

## 검토한 대안

- **Unity 안에서 폴더와 클래스만 나눔**: Unity 기능에 쉽게 의존하게 되어 서버로 옮기기 어렵다.
- **분리하지 않음 (일반 튜토리얼 방식)**: 처음은 가장 빠르지만 멀티를 붙일 때 사실상 다시 만들어야 한다.
