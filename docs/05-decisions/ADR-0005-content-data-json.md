# ADR-0005: 콘텐츠 규칙 데이터는 JSON이 원본, 시각 데이터는 ScriptableObject

- 상태: 승인
- 날짜: 2026-11-10

## 결정

생물·아이템·레시피·자원 같은 콘텐츠를 두 종류의 데이터로 나눈다.

| 종류 | 내용 | 원본 | 읽는 곳 |
|---|---|---|---|
| **규칙 데이터** | 체력, 속도, 성향, 인식 거리, 드롭, 재료, 레시피 | **JSON 파일** | Simulation, 전용 서버 |
| **시각 데이터** | 모델, 애니메이션, 소리, 이펙트 | ScriptableObject | Unity 클라이언트 |

- 두 데이터는 **콘텐츠 id**(예: `triceratops`)로 연결한다.
- 원본은 한쪽만 둔다. 규칙 값은 JSON에서만 고치고, ScriptableObject에 규칙 값을 복사해 두지 않는다.
- Unity 에디터 안에 **JSON 편집 창**을 만들어, 기획·아트 담당자가 코드 없이 규칙 값을 고칠 수 있게 한다.
- 생물 AI는 공용 **행동 부품**(배회, 인식, 도주, 공격)으로 만들고, 생물마다 어떤 부품을 쓸지와 값을 규칙 데이터에 적는다.
- 세이브 파일도 JSON으로 청크별로 저장하고, **세이브 버전** 번호를 넣는다.

## 이유

- 새 생물을 추가할 때 코드를 새로 쓰지 않고, 모델과 데이터만 추가하면 된다.
- 순수 C# Simulation([ADR-0004](ADR-0004-pure-csharp-simulation.md))과 서버가 Unity 없이 같은 데이터를 읽을 수 있다.
- 텍스트라서 에이전트가 읽고 고치기 쉽고, Git에서 변경 내역을 보고 충돌을 해결하기 쉽다.
- 나중에 모드 지원(Phase 5)으로 확장하기 쉽다.

## 결과

- JSON 편집 창을 직접 만들어야 한다.
- JSON 형식이 잘못되었을 때 바로 알 수 있도록 데이터 검증(스키마 또는 로드 시 검사)이 필요하다.

## 검토한 대안

- **ScriptableObject만 사용**: 편집은 편하지만 서버와 모드에서 읽기 어렵다.
- **ScriptableObject가 원본이고 JSON으로 내보내기**: JSON을 직접 고치면 안 되므로 에이전트와 모드의 장점이 사라진다.
- **생물마다 코드 작성**: 생물이 늘수록 코드도 늘어난다.
